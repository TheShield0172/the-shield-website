# Security Policy — THE SHIELD Public Pilot

**Release status:** Public Michigan FOIA drafting and blank educational forms; isolated fictional-data-only Case Vault security-review candidate. No production confidential-evidence intake, no account service or payment checkout.

## How to report a potential security issue

- **Do not** place a real record, screenshot of a personnel or agency system, confidential log, password, API key, test credential or exploit payload containing personal data in a public GitHub issue.
- If GitHub exposes a **private vulnerability-reporting** control for this repository, use that instead of a public comment. Otherwise, open a minimal public issue requesting a private contact method with **no exploit details or sensitive data**.
- Use fictional data and a nonproduction browser profile for reproduction. Never test another user or agency system without authorization.
- Include the relevant commit ID, general affected feature, browser version and non-sensitive reproducible steps only through an appropriate private channel.
- Do not attempt denial-of-service, access other people’s accounts, scrape private records or upload confidential content to our demonstration sites.

## Boundaries

- No current claim of independent security certification, CJIS approval, validated chain of custody or legal suitability for evidence retention.
- We cannot promise bounty payments, paid commissions, guaranteed response times or compensation. Do not buy or perform external services on behalf of THE SHIELD without the owner's explicit agreement.
- The public FOIA tools provide educational drafting, not legal advice.
- No new services, recurring expenses, checkout, or private-data collection should be enabled without approval and an appropriate review.

For public non-sensitive feature feedback, use the [Founding Tester page](https://the-shield-public-preview.onrender.com/pilot.html).
